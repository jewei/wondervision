# M2 editing correctness

Implemented through source commit `31bc6b0170df557053e92fc393549bf2bdb265f6`.
Verification used Go 1.27.3, MyGo v0.7.4, Debian 13 x86_64, X11 and software
rendering. The shared desktop failed to start, so both final native runners used
an isolated Xorg dummy display `:99` and XFWM. These were real MyGo windows and GTK
file choosers. No internal file-open or document-state endpoint replaced them.
Only the `e2e` build links a private Unix-socket automation plugin.

## Result

M2 saves only on explicit Save/Save As, retains newer edits made during I/O,
preserves supported UTF-8/BOM/LF/CRLF/final-newline formats and mode bits, blocks
known disk conflicts, watches open files without polling, and offers reviewed
recovery of private non-sensitive drafts. Workspace create/rename/move/delete
use rooted operations and guard against traversal, symlink escape and collisions.
Quick Open, search, palette and release hardening remain later milestones.

The three verification layers have separate scope:

- **Guardrails:** immutable save plans, matching receipt tokens, explicit
  fingerprints/overwrite approvals and small filesystem services. The AST check
  in `internal/guardrails` rejects direct app filesystem writes, misplaced editor
  widgets, network/process/database imports, periodic idle paths and unconfirmed
  overwrite entry points. This is an ordinary static test, not a security proof.
- **Empirical:** actual filesystem tests, race detection, native user journeys,
  bounded production callback schedules and real-code fault mutations.
- **Formal:** a finite TLA+ model of one document's save/edit/conflict ordering.
  It checks the design within stated bounds and does not verify all Go code or
  the filesystem, recovery, toolkit or whole application.

## Review and fixes

An independent GPT-6 Astra review found approval lifetime and watch-enrollment
bugs. Quit approval now covers exact document versions; overwrite approval binds
the reviewed fingerprint; watch enrollment performs a guarded reconciliation.
The finite model was refined to separate validation from replacement.

A final GPT-6 Astra review reproduced three recovery findings: two sessions could
race when replacing a draft, confirmed Reload retained a recovered copy, and a
failed claimed-copy cleanup could finish quit. Recovery check/write/remove now
uses one nonblocking OS advisory lock, released on process exit. Reload consumes
the recovery claim; cleanup failure revokes pending quit. New regressions and a
missing-lock mutation demonstrate the fixes, and the reviewer rechecked them
without finding a new blocker. A further self-audit added a
queue-saturation regression: pending quit is also revoked if cleanup cannot be
enqueued. The last native rerun and race/build checks include that guard.

A subsequent native run caught an Explorer accessibility crash when reopening
the folder: resetting an inline `OutlineState` cleared the list frame still held
by the rendered view. Explorer generations now have separate state pointers and
label closures retain their own generation. The regression and destructive-reset
mutation are under `explorer-lifetime/`. The failed run's raw crash and cleanup
record are `m2-failed-explorer.log` and `m2-failed-explorer-cleanup.json`; it is not
counted as a pass. Both native journeys passed on the corrected source. These
last queue/lifetime fixes were tested after the independent review.

Review was independent across GPT models; cross-vendor review was unavailable.
No run transcript directory was available, so the final audit inspected source,
decision rows and artifacts rather than certifying conversational history.

## Limits

- Atomic save checks content twice, but rename is not compare-and-swap. An outside
  write between the final check and rename can be overwritten. The unmodified
  model intentionally violates `NoRacedOverwrite`, and
  `TestFinalReplaceWindowIsNotCompareAndSwap` reproduces that exact ordering.
  See the five-step path in `save-statechart/final-window-limit/report.md`.
- Linux amd64 was exercised. The exclusive move adapter also exists for Linux
  arm64; other platforms return unsupported for rename/move. Recovery locking has
  Unix adapters and fails closed on Windows/unsupported targets. Other platforms
  have not been built or run in this milestone.
- Recovery lock contention reports an error and retries after another edit; it
  does not poll. Prior-session drafts require Recover or Discard. Metadata review
  is capped at 128 records per listing; additional copies remain preserved.
- Permanent deletion is labelled and confirmed. MyGo v0.7.4's documented
  `Shell.TrashItem(path)` accepts a full path and provides no rooted operation;
  using it would weaken the workspace boundary under a parent symlink swap.
  The specification permits confirmed permanent deletion when no supported safe
  API is available. No large Trash dependency or hidden workspace staging is added.
- Atomic replacement preserves ordinary mode bits where supported; ownership,
  ACLs, hard-link relationships and every filesystem metadata detail are not
  universally preserved. Tests cover uniform LF and CRLF, not arbitrary mixed
  per-line endings. Only UTF-8 text up to 20 MiB is loaded.
- No new M2 performance number is claimed. The 10-minute foreground/minimized
  and 24-hour release measurements remain M4; `PERFORMANCE.md` records the earlier
  short samples with their actual source commits and measurement limits.
